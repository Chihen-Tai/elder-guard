**彈窗的形式**：**全螢幕 Activity**，由 App 把自己的工作視窗從背景搬到最前面。不是通知、不是懸浮視窗，也不是網頁推播。
**真正的入口**：Google 廣告聯播網，透過官方 YouTube 播放。廣告內容本身就是假警告，這一部分守門員**無法介入**（見第 5 節）。

**無法用紀錄證實的部分（標示為未證實）：**
- 「**安裝後圖示消失**」：這段 logcat 中沒有元件停用或捷徑移除的事件，而且 App 已經移除，無法再檢查。偵測功能仍然涵蓋這種情況（見測試 4）
- 它用哪一種豁免條件繞過背景啟動限制：vivo 的紀錄沒有寫出。在標準 Android 16 模擬器上，**沒有「顯示在其他 App 上層」權限時，同樣的行為 2/2 次被擋下**（見測試 2），所以它一定用了某種豁免或 vivo 的放寬規則，但無法確定是哪一種

## 2. 漏判與沒有防護的根本原因

| # | 原因 | 證據 |
|---|---|---|
| R1 | **手機上的守門員（0.1.0-ui）只是介面原型，完全沒有掃描功能**：「現在檢查一次」只等 1.8 秒，然後過濾展示用的資料 | `MainActivity.check()` 原始碼 |
| R2 | **沒檢查就宣稱安全**：沒有任何發現時，首頁就顯示「您的手機目前很安全」。使用者在 19:06:04 和 19:06:44（廣告轟炸期間）開啟守門員，看到的就是這句話 | 原始碼；usagestats 中 `org.elderguard` 的 ACTIVITY_RESUMED 紀錄 |
| R3 | **沒有任何執行期監測**：沒有服務、沒有使用情況存取、沒有通知監聽，所以不可能看到「哪個 App 在其他 App 上跳畫面」 | 原始 Manifest 只有 2 個權限 |
| R4 | 判定引擎（EGDA）只存在於電腦上的 Python 程式中，手機上沒有 | `engine/egda.py` |
| R5 | EGDA 是**靜態**分析；即使移植到手機，對這個 App 也不一定能判為「要小心」（Play 安裝、沒有否決條件）。**這次事件的決定性證據是行為**（在其他 App 上跳全螢幕廣告），不是靜態特徵 | ALGORITHM.md 第 11 節：靜態召回率 80% |

逐項確認你提出的問題：
- 掃描是否涵蓋沒有圖示的套件：原版**根本沒有掃描**；新版使用 `QUERY_ALL_PACKAGES`，連沒有啟動頁的套件也會列出（vivo 實測列出 55 個使用者 App，勾選顯示系統 App 後共 101 個）
- 是否把「來自 Google Play」當成安全保證：原版沒有判斷；新版的安裝來源只是加分項之一，不會因為來自 Play 就降低風險（這次的 App 就是從 Play 來的）
- 是否只顯示分數而沒有事件監測：原版連分數都沒有；新版以**行為證據為主**、靜態分數為輔，且兩者分開顯示（「已確認」與「疑似」）
- 是否在服務沒有執行時仍顯示「防護中」：原版根本沒有服務，卻暗示安全；新版以「服務正在執行＋90 秒內有心跳」判斷，並逐項列出缺少的權限與無法提供的功能

## 5. 仍受 Android 限制的部分

| 限制 | 影響 | 替代方案 |
|---|---|---|
| 看不到其他 App 的畫面內容（除非使用無障礙服務） | **YouTube 或網頁「裡面」的假警告廣告無法攔截或歸因**（這次的入口就是這種） | 教長輩「手機不會叫你更新 PDF 閱讀器」；Play 商店加上應用程式鎖；私人 DNS 可以擋掉部分 App 內廣告，但**擋不了 YouTube 廣告** |
| 一般 App 不能強制停止、停用或解除安裝其他 App | 守門員只能帶到設定頁 | 詳細頁的「前往設定移除」加上「先按強制停止」的說明；已驗證這個流程有效 |
| 懸浮視窗沒有來源紀錄（不會產生畫面切換事件） | 無法指出「這個懸浮廣告是誰畫的」 | 列出有上層顯示權限的 App；Android 11 以後只能開到**全部 App 的清單**頁 |
| 背景跳畫面時，守門員的提醒只能以通知呈現，而且會被廣告蓋住 | 長輩要在廣告之間的空檔操作 | 使用者先前同意過「選用的上層彈窗」（PLAN.md），尚未實作 |
| 被強制停止或廠商省電機制殺掉後，在使用者重新打開前都沒有保護 | 無法提醒 | 引導設為「不限制電池用量」；vivo 或 OPPO 的自啟動白名單需要手動設定 |
| 使用情況存取、通知存取都要使用者自己在設定中開啟 | 沒開就無法歸因 | 首頁如實列出缺少的項目並提供入口；「找出剛剛跳出來的廣告」可以回頭查，不必事先開著 |

## 8. 追加：自動關閉「連續跳出」的廣告（0.3.x，使用者要求）

**規則**（使用者決定：「連續跳出才攔截」）：同一個 App 在使用者用別的 App 時跳出全螢幕廣告，**第 1 次只記錄**；30 分鐘內**第 2 次起**自動關閉。

**實作**：選用的無障礙服務 `monitor/AdCloserService.kt`，預設關閉，必須由使用者在系統「無障礙」設定中開啟。
- 只接收「畫面切換」事件，`canRetrieveWindowContent=false`，**不讀取畫面內容**
- 動作只有返回鍵；廣告攔住返回鍵時（試 2 次）改按回桌面
- 關閉後用系統畫面紀錄確認最上層是誰（無障礙事件不一定會送出）
- 系統介面（橫幅通知）的事件不列入判斷
- 使用者打開的 App 裡自己的插頁廣告不算
- 同一個 App 疊在自己沒被關掉的廣告上再跳一次（間隔 ≥ 5 秒），算新的一次
- 判斷邏輯：`detect/PopupPolicy.kt`；介面：首頁「自動關閉連續跳出的廣告：開啟中／沒有開啟」，詳細頁「守門員已自動幫您關掉 N 次」

**驗證（模擬器 Android 16）**

| 情境 | 結果 |
|---|---|
| 第 1 次跳出 | 沒有動作，廣告留在畫面上 ✅ |
| 第 2、4 次：會攔住返回鍵的廣告 | 返回鍵 ×2 無效，接著回桌面，約 **1.8 秒**關閉 ✅（代價：使用者原本的 App 被切到背景） |
| 第 3、5 次：一般廣告 | 返回鍵 1 次，**0.25 秒內**關閉 ✅ |
| 同時段的正常操作（設定、Chrome、網頁、正常 App、通知） | 0 次誤關 ✅ |
| 正常 App 內自己的插頁廣告（連續 3 次） | 0 次誤關 ✅ |
| 真實事件重播（vivo 紀錄） | 只針對 `com.mjh.profitorabalancepointcalc`，除了第 1 次，其餘都會關閉 ✅（單元測試） |
| 服務的 App 更新後、重新開機後 | 自動恢復 ✅ |
| 介面計數 | 跳出 5 次、關掉 4 次，與紀錄一致 ✅ |
| 從 App 開啟設定 | 開到「無障礙」清單頁 ✅ |

**這一輪測試中發現並修正的錯誤：**
1. 使用 `ACCESSIBILITY_DETAILS_SETTINGS` 需要系統權限，**守門員直接當掉** → 改開清單頁，所有開啟外部頁面的地方都加上保護
2. 返回鍵關掉廣告之後，沒有收到被蓋住 App 的事件 → 同一個 App 的下一次跳出被忽略 → 改用系統畫面紀錄確認最上層
3. 第 2 次廣告疊在沒被關掉的第 1 次上面 → 被當成 App 內切換 → 加入「重新跳出」規則，兩個偵測器共用

**限制與代價：**

- 退回桌面時，使用者原本的畫面會被切到背景
- 長輩**連續兩次**點廣告 App 的通知打開廣告頁，第二次會被關掉
- 關閉只是爭取時間，**根本解決仍然是解除安裝**
